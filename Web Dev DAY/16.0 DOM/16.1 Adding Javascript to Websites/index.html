Adding Javascript to Websites

INLINE JS
Best Practices
1- Avoid Overusing Inline JS: For larger projects, it’s better to use external JS files (e.g.) to keep code maintainable and separate from HTML.
2- Security Note: Be cautious with inline JS if it involves user input, as it can be vulnerable to XSS (Cross-Site Scripting) attacks.
3- Performance: Inline JS in without defer or async can block HTML rendering, so placing it at the end of is often preferred.

INTERNAL JS When to Avoid Internal JS
1- Large Projects: Use external JS files for better modularity and team collaboration.
2- Performance-Critical Sites: External files can be cached by browsers, reducing load times.
3- Reusable Code: Internal JS is tied to one HTML file, limiting reuse.

EXTERNAL JS (peferred)
When to Use External JS
1- Large projects with reusable code.
2- Team collaboration (easier to manage in version control).
3- Performance-critical sites (caching benefits).
